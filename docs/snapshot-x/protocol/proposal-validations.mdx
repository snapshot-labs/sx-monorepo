---
title: "Proposal validations"
---

**Proposal validation strategy is used to determine whether a particular `author` is allowed to create a proposal.** 

Each Space has to set a proposal validation strategy which consists of an address and a set of `params` that are stored in the space. These strategies should have the following interface: 

```solidity
function validate(address author, bytes calldata params, bytes calldata userParams) external returns (bool);
```

* `author`: The author of the proposal.
* `params`: Parameter array set in the space contract that is the same for every user of the Strategy.
* `userParams`: Parameter array submitted by the `author` when they create a proposal, and can therefore be different for each user. 

There is no requirement to use either of these parameter arrays in your strategy, in which case you can just pass an empty array.

DAOs are free to write their own custom strategies that suit their own needs however we provide the following approaches:

### Proposition power

A strategy that validates an `author` to create a proposal if their `propositionPower` calculated from a set of Voting strategies exceeds a `proposalThreshold` value. It means that if the proposal threshold is set to `5`, the author needs to have at least `5` Proposition power to create a proposal. This strategy uses the same logic as [Voting strategies](/snapshot-x/protocol/voting-strategies), so refer to that section for more information.

When calling this strategy, `params` should be:

```solidity
uint256 proposalThreshold = ...
Strategy[] allowedStrategies ...
params = abi.encode(proposalThreshold, allowedStrategies);
```

`userParams` should contain the indexed strategies that the `author` has power with:

```solidity
IndexedStrategy[] userStrategies = ...
userParams = abi.encode(userStrategies);
```

### Active proposal limiter 

A strategy that validates an `author` to create a proposal if the `author` has not exceeded a limit of `maxActiveProposals`.

Each time an `author` creates a proposal, a counter is incremented up to a limit of `maxActiveProposals`. After this point, no more proposals can be created until a `cooldown` period has elapsed since the most recent proposal they created.

Using this strategy can help to prevent proposal creation spam in your space. 

### Proposition power with active proposal limiter

A strategy that combines the two strategies above. An `author` can create a proposal only if their `propositionPower` is at least the `proposalThreshold` and they have not reached the limit of `maxActiveProposals` within the `cooldown` period. It is available in the Snapshot interface as "Voting power with cooldown".

When calling this strategy, `params` should be:

```solidity
uint256 cooldown = ... // In seconds
uint256 maxActiveProposals = ... // Cannot be 0
uint256 proposalThreshold = ...
Strategy[] allowedStrategies ...
params = abi.encode(cooldown, maxActiveProposals, proposalThreshold, allowedStrategies);
```

`userParams` is the same as for the Proposition power strategy.

### Proposition power with active proposal limiter V2

The same as the strategy above, except that the `author` can have the proposition power computed at a recent block, at most `maxBlockAge` blocks old, rather than at the block the proposal is created in. This lets strategies whose power is signed offchain for a given block be used. A block number of `0` computes it at the block the proposal is created in, like the strategies above. A `cooldown` of `0` disables the active proposals limit.

When calling this strategy, `params` should be as follows. The three limits are packed in a single `uint96` so that they take one storage slot instead of three, which makes proposals cheaper:

```solidity
uint256 proposalThreshold = ...
Strategy[] allowedStrategies ...
uint32 maxActiveProposals = ... // Cannot be 0 if cooldown is not 0, ignored otherwise
uint32 cooldown = ... // In seconds, 0 disables the limit
uint32 maxBlockAge = ... // In blocks, 0 only accepts the current block
uint96 limits = (uint96(maxActiveProposals) << 64) | (uint96(cooldown) << 32) | maxBlockAge;
params = abi.encode(proposalThreshold, allowedStrategies, limits);
```

`userParams` should contain the block the proposition power is computed at, either `0` for the current block or a block that isn't in the future or older than `maxBlockAge` blocks, and the indexed strategies that the `author` has power with:

```solidity
uint32 blockNumber = ... // 0 for the current block
IndexedStrategy[] userStrategies = ...
userParams = abi.encode(blockNumber, userStrategies);
```

### And more!

These strategies can be combined and extended to provide flexible Proposal validation mechanisms. The interface for Proposal validation strategies can be found [here](https://github.com/snapshot-labs/sx-evm/tree/main/src/proposal-validations).
